## Связь BRD и SRS

BRD описывает бизнес-потребности проекта: зачем создается сайт, кому он нужен и какие результаты ожидаются. SRS уточняет системные требования: какие функции должна выполнять система, какие ограничения должны соблюдаться и как система взаимодействует с пользователями.

## Требования ГОСТ Р ИСО/МЭК 15288-2005

В соответствии с ГОСТ Р ИСО/МЭК 15288-2005 стадия разработки начинается с технического уточнения системных требований и проектных решений. Эти требования преобразуются в реализуемый продукт или прототип, который способен выполнять заданные функции в процессе использования.

Для проекта сайта абитуриентов это означает, что на стадии разработки должны быть определены:

- системные требования;
- архитектура сайта;
- интерфейсы пользователя;
- API взаимодействия клиента и сервера;
- база данных;
- средства проверки и тестирования;
- документация для разработки и сопровождения.

## Результаты стадии разработки

Для проекта должны быть подготовлены следующие результаты:

| Результат | Реализация в проекте |
| --- | --- |
| Уточненные системные требования | BRD/SRS-описание, страницы пользователей и архитектуры |
| Архитектура системы | логическая и физическая архитектура, UML-диаграммы |
| Документация верификации и валидации | критерии приемки, тестирование API и интерфейса |
| Подтверждение соответствия требованиям | проверка функций сайта и базы данных |
| Проектная программная документация | Docusaurus-документация и OpenAPI-файл |
| Спецификации интерфейсов | описание REST API и форматов JSON |
| Прототип системы | React-сайт с данными из `db.json` |
| Идентифицированные риски | таблица рисков в плане проекта |

## Критерии перехода к следующей стадии

Переход к дальнейшей разработке возможен, если:

- определены цели и границы проекта;
- описаны пользователи и их задачи;
- подготовлена архитектура;
- описаны API и база данных;
- создан прототип интерфейса;
- определены риски и способы их уменьшения.
